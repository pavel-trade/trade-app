# Ревью Pine-кода по чек-листу ловушек v6

Файлы: `pine/tw_speedometer_pro.pine`, `pine/tw_blind_zone_pro.pine`.
Компилятора TradingView у меня нет. Проверка шла в три слоя:

1. построчное ручное ревью (ниже, по пунктам);
2. механический линтер `reference/pine_lint.py` (его тесты лежат в `reference/tests/test_pine_lint.py`,
   в том числе негативные — линтер действительно ловит каждое нарушение);
3. эталон на Python `reference/speedometer.py` с теми же формулами и тестами на синтетике.

Итог линтера: `python reference/pine_lint.py pine/*.pine` → 0 замечаний.

## Что ещё проверено вручную

- **Логарифм и проценты.** `f_tr(x) = 100 * ln(x)`; AO — от `100 * ln(hl2)` (логарифм медианы). Тест `test_log_makes_scale_invariant`: при умножении цены на 1000 значения MACD не меняются.
- **ATR-нормировка.** TR считается в тех же единицах, что и MACD (логарифм или цена), `ATR = ta.rma(TR, 14)`; делятся MACD и AO, сигнальная — EMA уже нормированного MACD (так же в Python).
- **Слепая зона.** Экстремум обновляется до проверки смены режима, поэтому бар пересечения входит в зону; противоположная граница (индикатор на цене) — `math.min/max` «на ходу». Тест `test_blind_zone_from_extreme_to_cross`.
- **Дивергенции.** Цена сравнивается по `low`/`high` в окне вокруг пивота (окно ≤ «баров справа», иначе заглядывали бы в будущее). Задержка сигнала = `pR` баров (тест проверяет `confirm_bar = pivot_bar + 5`).
- **Анализ волны.** Бар точки — первый бар с `time_close > t`. Отрезок k включает оба конца (`ptBar[k-1]..ptBar[k]`), как в Python. Направление — по `close` точек 0 и 5.
- **Оповещения.** `alert()` только при `barstate.isconfirmed` с `alert.freq_once_per_bar_close`.

## Оставшиеся риски (проверить на TradingView)

1. **Затравка `ta.ema`.** Python использует формулу `pine_ema` из справки (seed = первое значение). Если встроенная `ta.ema` затравливается иначе (например, SMA), значения разойдутся только на первых барах истории: вклад затравки затухает как (1 − 2/35)^n — через 300 баров ≈ 10⁻⁸. Сверять нужно на барах далеко от начала истории.
2. **Равные значения в пивотах.** В Python «плато» даёт пивот на самом левом баре (центр строго больше левых и не меньше правых). Точное правило `ta.pivothigh` при равенстве не документировано; на реальных float-данных равенства редки.
3. **`table.merge_cells` после `table.clear` на каждом тике.** Таблица анализа волны очищается и объединяет ячейки при каждом исполнении на последнем баре. Если TradingView начнёт ругаться на повторное объединение — убрать `merge_cells` (текст останется в первой колонке).
4. **ТФ таблицы ниже ТФ графика.** `request.security` к младшему ТФ формально работает, но значение ненадёжно; таблица пишет «ТФ ниже графика» вместо значения.
5. **`time_close` и точки волны** на символах с сессиями (акции, фьючерсы) и на дневках: время закрытия дневного бара — конец сессии. Python-эталон берёт время открытия следующего бара; для 24/7 рынков это совпадает, для акций точка может сдвинуться на бар, если ввести время внутри разрыва сессии.
6. **Объекты далеко в прошлом.** Боксы слепых зон рисуются по `bar_index`; при режиме длиннее нескольких тысяч баров TradingView может отказать в рисовании. Метки точек волны рисуются по времени (`xloc.bar_time`), им это не грозит; макс. расстояние пивотов ограничено 1000 баров.
7. **Отрисовка на живом баре.** Пивот, подтверждённый на незакрытом баре, может нарисоваться и исчезнуть до закрытия бара (откат состояния Pine на каждом тике). Оповещения от этого защищены (`barstate.isconfirmed`, «раз за закрытие бара»).
8. **`chart.bg_color` при смене темы.** Индикатор пересчитывает цвета при пересчёте скрипта; если сменить фон графика, тема «Авто» обновится после перезагрузки или изменения настроек.

## Найдено и исправлено в ходе ревью

- Метка без текста для первого отрезка «трёх пиков» → метка создаётся только при непустом тексте.
- Лимит удаления линий не учитывал дубли на графике цены → `keepN = maxDivObj × (2 или 4)`, укладывается в 500.
- Метки точек волны по `bar_index` → по времени (`xloc.bar_time`), иначе старые волны могли не нарисоваться.
- Нет защиты от `slow ≤ fast` в пресете «Свои» → `runtime.error` с понятным текстом.
- Макс. расстояние между пивотами не ограничено → `maxval = 1000`.
- Текст «неопределённо» для случая «волна 4 не вернулась к нулю» в Pine и Python приведён к одному виду.
