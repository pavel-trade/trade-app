# Ревью `pine/tw_market_map.pine` по требованиям

Ревью «TW Спидометр» — `docs/speedometer/review.md`, «TW Спидометр Pro» и «TW Слепая зона Pro» —
`docs/pro/review.md`.

Компилятора TradingView нет. Проверка шла в три слоя:
1. самопроверка после каждого модуля M1–M11 и итоговое построчное чтение файла;
2. линтер `reference/pine_lint.py` — 0 замечаний. У каждой проверки есть негативный тест,
   `tests/test_map.py` прогоняет линтер на этом файле;
3. эталон `reference/map.py` — тот же конечный автомат бар за баром, с тестами `tests/test_map.py`.

## Требования

| # | Требование | Статус | Как проверено |
|---|---|---|---|
| 1 | `input.time` — defval только числом | ✅ | Все точки — `input.time(0, …)` (0 = не задано). Якорь AVWAP — `1789430400000` (15.09.2026 00:00 UTC) с комментарием. `timestamp()` в файле нет. Линтер. |
| 2 | `ta.*` и `request.*` на каждом баре, глобально | ✅ | Все `ta.*` (EMA, SMA, ATR, пивоты, highest/lowest/…bars, crossover, `math.sum`) — на отступе 0, в переменные. В `if`, циклах и тернарных операторах используются только готовые значения. `request.*` нет вовсе (MTF здесь не нужен, профиль — без `request.security_lower_tf`). Функции с `ta.*` отсутствуют. Линтер. |
| 3 | bool не бывает na; ленивые and/or | ✅ | Все bool инициализированы. Ленивость `and` используется как защита: `swDir.size() > 0 and swDir.last() == 1`, `not same or (… swPx.last())`. Сравнения с na дают false: учтено в `low < rnPx`, `cBar != cBar[1]`. |
| 4 | Состояние через var/массивы; циклы по истории ограничены, с `max_bars_back` | ✅ | Свинги, ноги, малые пивоты, слепые зоны, точки по датам, ручные ноги A-B-C — через var. Нога в режиме пивотов копится с лагом L баров, поэтому к подтверждению пивота она посчитана без цикла по истории. Единственный цикл по истории — профиль объёма на последнем баре, ≤ 3000 баров, ряды `hiS/loS/vS` с `max_bars_back(…, 5000)` и проверкой «диапазон дальше 5000 баров». Остальные циклы фиксированные: 2 типа пивотов, ≤ 6 точек, ≤ 40 малых пивотов, ≤ 100 уровней профиля, ≤ 16 уровней. |
| 5 | Лимиты объектов, удаление старых, `set_*` вместо пересоздания | ✅ | `max_lines/labels/boxes_count = 500`, `max_polylines_count = 10`. Пулы, создаваемые один раз и обновляемые через `set_*`: уровни M4 (16 линий и 16 подписей, 3 полосы), каналы (7), разметка (5 линий, 6 подписей), профиль (100 боксов и 3 линии), правило 100–140, пунктир ZigZag. Растущие наборы — массив + `shift().delete()`: ZigZag ≤ 100, слепые зоны ≤ 150, метки «Триггер» ≤ 50. При замене свинга линия и подпись двигаются через `set_xy2/set_xy`. |
| 6 | Таблицы — var, обновление на `barstate.islast` | ✅ | `var table chkT`, `var table waveT`; заполнение — только в `if barstate.islast`. Линтер. |
| 7 | Подтверждённое не перерисовывается; перерисовываемое помечено | ✅ | Свинги появляются только подтверждёнными (через L баров или после разворота на %). Последний отрезок ZigZag — пунктир с подписью «может перерисоваться». Неподтверждённый C подписан и в таблице, и на уровне. AVWAP от него бледный. Метка «Триггер» — только при `barstate.isconfirmed`, `alert()` — тоже. |
| 8 | ≤ 64 plot; ограничение тяжёлых модулей | ✅ | 13 `plot` + `fill` + `bgcolor`. Профиль — только на последнем баре, ≤ `vpMaxBars` баров × ≤ 100 уровней. |
| 9 | Без ошибок и предупреждений компилятора | ⚠️ не проверено | Нужен компилятор. Устранено найденное: объявление функции внутри `if` (заменено на тип `TLv` и глобальную `f_lv`), цикл `for i = 0 to size - 1` по пустому массиву (в Pine он идёт вниз — добавлена защита). Затенения глобальных имён локальными нет. |

## Найдено и исправлено в ходе работы

- Функция `f_add` была объявлена внутри блока `if` — в Pine так нельзя. Заменена на тип `TLv`
  и глобальную `f_lv`; в линтер добавлена проверка «функции только на верхнем уровне».
- `for i = 0 to rName.size() - 1` при пустом массиве — Pine идёт вниз (0, −1) → `get(-1)`. Добавлена защита.
- Бары профиля пересоздавались на каждом тике → пул из 100 боксов через `set_*`.
- Знак правила «B не за началом A» в эталоне — исправлен тестом.
- Определение конвергенции: сравнение с предыдущим малым минимумом не работало. После сильного
  импульса скорость (MACD 5/34) на первом минимуме коррекции ещё положительна. Принято правило,
  близкое к методике: на C скорость слабее экстремума скорости коррекции хотя бы на 10 % (настраивается).

## Оставшиеся риски (проверить на TradingView)

1. **Компиляция** — главный риск: файл в 1450 строк ни разу не компилировался.
2. **`ta.lowestbars/highestbars` при равных значениях.** Python берёт самый ранний бар, Pine
   может брать другой. Влияет только на бар текущего экстремума C при точном равенстве цен.
3. **`ta.pivothigh/pivotlow` на «плато»** не документированы; в эталоне пивот — самый левый бар плато.
4. **Затравка `ta.ema`.** В эталоне seed = первое значение. Сверять дальше 300 баров от начала истории.
5. **Нагрузка.** Профиль объёма (до 3000 баров × 100 уровней) пересчитывается на каждом тике
   последнего бара. На медленном устройстве уменьшите «Не больше баров в диапазоне».
6. **Сравнение `!=` с na** в `cBar != cBar[1]`: в начале истории значение может быть «не изменилось» —
   это влияет только на разрыв линии AVWAP, не на расчёты.
7. **Метки уровней** раздвигаются на 0,7 × ATR(14). На сильно сжатом масштабе графика они всё же
   могут касаться друг друга.
8. **Ручные даты на символах с сессиями.** Бар точки — первый с `time_close > даты`; дата внутри
   разрыва сессии даёт следующую свечу.
