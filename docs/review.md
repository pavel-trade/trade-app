# Ревью `pine/tw_speedometer.pine` по чек-листу ловушек Pine v6

Индикатор «TW Спидометр — скорость + ускорение». Ревью «TW Спидометр Pro» и «TW Слепая зона Pro»
лежит в `docs/pro/review.md`.

Компилятора TradingView нет, поэтому проверка шла в три слоя:

1. ручное построчное ревью после каждого модуля (1–7) и итоговое — ниже;
2. линтер `reference/pine_lint.py` (0 замечаний; у каждой проверки есть негативный тест
   в `reference/tests/test_pine_lint.py`, а `tests/test_speedometer.py` прогоняет его на этом файле);
3. эталон на Python `reference/speedometer.py` с теми же формулами и тестами `tests/test_speedometer.py`.

## Чек-лист

| # | Требование | Статус | Как проверено |
|---|---|---|---|
| 1 | `input.time` — defval только числом (const int) | ✅ | Все шесть точек: `input.time(0, …)`, 0 = «не задано». `timestamp()` в файле нет. В комментарии — пример `1789430400000 = 15.09.2026 00:00 UTC`. Линтер проверяет каждый `input.time/int/float`. |
| 2 | `ta.*` и `request.security` — на каждом баре, на глобальном уровне | ✅ | `ta.ema` — только в теле `f_speed` (на его верхнем уровне); `f_speed` вызывается безусловно на глобальном уровне и внутри трёх `request.security`. `ta.percentile_linear_interpolation`, `ta.pivot*`, `ta.lowest/highest`, `ta.crossover/crossunder` — на отступе 0, в переменные; потом используются в `if`. Фильтр «только после закрытия бара» применяется к уже посчитанным `bool`. Линтер отслеживает и функции, внутри которых есть `ta.*`. |
| 3 | bool не бывает na; ленивые `and`/`or` | ✅ | Все `bool` инициализированы (`false` или выражение). В `and`/`or` нет `ta.*` и побочных эффектов. Сравнения с `na` дают `false`: учтено в `pAcc > 0`, `ptBar.get(k) == bar_index`, `pxLoAtPivot < loPx`. |
| 4 | Состояние через `var`; циклы по истории — ограничены и с `max_bars_back` | ✅ | Пивоты, экстремумы отрезков 1-3-5 (с их временем), точки волны — через `var`, без циклов по истории. Единственный цикл по истории — перестроение линии ускорения в авто-режиме на `barstate.islast`: длина ≤ `autoLen` ≤ 2000, `max_bars_back(accHist, 2000)`. Остальные циклы — фиксированные (6 точек, 5 отрезков, удаление ≤ 6 меток). Линтер требует `max_bars_back` для истории по счётчику цикла. |
| 5 | Таблицы и подписи — один раз через `var`, обновление на `barstate.islast` | ✅ | `var table stTbl`, `var label accLbl`, `var polyline accPoly`; заполнение и `set_*` — только в `if barstate.islast`. Метки пиков 1-3-5 пересоздаются на последнем баре со старыми удалёнными. |
| 6 | `max_lines_count`, `max_labels_count` и чистка | ✅ | `max_lines_count = 300, max_labels_count = 300, max_polylines_count = 5`. Дивергенции: массивы + `shift().delete()`, ≤ 100 линий и ≤ 100 меток; пики 1-3-5: ≤ 6 меток и 2 линии; одна подпись, одна polyline. |
| 7 | Нет синтаксиса v4/v5 | ✅ | `indicator`, `request.security`, `ta.*`, `chart.point`, `polyline`, методы массивов; нет `study`, `security`, `transp`, `when`. Линтер. |
| 8 | Без предупреждений компилятора | ⚠️ не проверено | Нужен компилятор. Устранены известные источники: условные вызовы `ta.*` и функций с `ta.*`; затенение глобальных имён локальными (имена не совпадают, одноимённые локальные — только в соседних блоках). |

## Оставшиеся риски (проверить на TradingView)

1. **Компиляция.** Самый важный риск: код ни разу не компилировался.
2. **`ta.percentile_linear_interpolation`.** Python считает ранг как `p/100·(n−1)`. Если в Pine формула ранга
   другая, авто-множитель в таблице может отличаться от Python на доли процента. На смысл это не влияет: масштаб всё равно один на всю линию.
3. **Затравка `ta.ema`.** В эталоне seed = первое значение (формула `pine_ema`). Если встроенная `ta.ema`
   затравливается иначе, разница видна только в начале истории. Сверять нужно свечи дальше 300 баров от начала.
4. **`hline` с цветом от ввода.** Уровни ±X отключаются прозрачным цветом (`lvl > 0 ? … : прозрачный`).
   Если компилятор не примет `input color` в `hline`, замените на `plot(lvl > 0 ? lvl : na)`.
5. **Polyline в авто-режиме** перестраивается на каждом тике последнего бара (≤ 2000 точек). Если на
   медленном устройстве это тормозит, уменьшите «окно N».
6. **Сигналы на живом баре.** С выключенной опцией «только после закрытия бара» треугольник может
   появиться и исчезнуть до закрытия бара. Это обычный откат состояния Pine, на истории его нет.
7. **Точки 1-3-5 на символах с сессиями.** Бар точки — первый с `time_close > даты`. На дневках акций
   время закрытия = конец сессии, поэтому дата внутри разрыва сессии может сдвинуть точку на бар относительно эталона.
8. **Равные значения в пивотах.** Как `ta.pivothigh` ведёт себя на «плато», не документировано; в эталоне пивотом считается самый левый бар.
9. **Текст профиля.** В Pine к названиям диагоналей добавлено «(затухание)» / «(возрастание)», в Python — без
   скобок. Классы совпадают.

## Найдено и исправлено в ходе ревью

- Подсказка режима «Полоса» говорила о квадратах, а рисуются треугольники (форма дублирует знак) → текст исправлен.
- Нет защиты от `slow ≤ fast` в пресете «Свои» → `runtime.error` с понятным текстом.
- Линтер не знал о `polyline` и циклах по истории → добавлены проверки `max_polylines_count` и `max_bars_back`.
