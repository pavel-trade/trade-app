# Исследование вклада пунктов чек-листа — отчёт

## Главное

1. **Реальные данные BTC в этом окружении получить не удалось.** Сетевая политика среды
   разработки закрывает биржевые API (Binance, Kraken, Coinbase, Yahoo отвечают 403).
   Поэтому выводы о BTC 2022–2026 здесь **не сделаны**. Скрипт готов: запустите его на своём CSV
   (команда ниже), и отчёт перезапишется реальными цифрами.
2. Вместо этого скрипт прогнан на **нулевом тесте** — трёх случайных блужданиях 4ч по 8760 баров
   (2022–2026 по датам). На случайном блуждании преимущества быть не может, поэтому
   любой «эффект» там — шум. Это калибровка: такого же масштаба «эффекты» на реальных данных
   нельзя считать находкой.
3. Что показал нулевой тест:
   - **все события:** средний R ≈ −0,05…−0,07 при любом L из 8/10/12, то есть примерно минус
     комиссия. Так и должно быть: модель сделки не создаёт преимущества сама по себе;
   - **периоды противоречат** (−0,2 R в первом, +0,07 R во втором) — на чистом шуме;
   - **статус «Триггер»:** 17–23 сделки (меньше 30, помечено ⚠) со средним R +0,3…+0,4.
     Это **случайность малой выборки**, а не преимущество: данные — случайное блуждание;
   - **у пунктов 2, 4, 6, 9 вклад меняет знак между периодами**, у остальных разница
     «с признаком / без» доходит до 0,3–0,4 R — тоже на шуме.

   Вывод для реальных данных: разница меньше примерно 0,3 R на выборке в сотни событий,
   выборка меньше 30 или смена знака между периодами — это не основание считать пункт полезным.
   Это согласуется с исходной оговоркой: механическая версия сетапа на BTC 2022–2026
   устойчивого преимущества не показала.

## Как запустить на реальных данных

```bash
# CSV с колонками time, open, high, low, close, volume (экспорт TradingView подходит)
python research/component_value.py BTCUSDT_4h.csv --split 2024-01-01
python research/component_value.py BTCUSDT_1d.csv BTCUSDT_4h.csv --split 2024-01-01 --zz-len 10
```

Параметры по умолчанию — как в индикаторе: L = 10 (рядом показаны 8 и 12), стоп C ∓ ATR(14) × 0,5,
цель 1,0 × волна 1 от C (лог-шкала), комиссия 0,1 % за сторону, удержание не дольше 200 баров.
Лучшие параметры **не подбираются**: соседние значения L нужны только для оценки устойчивости.

## Методика

- **Событие** — первый бар, на котором закрытие ушло за «первый триггер» (пункт 5 = ✓) при
  существующей структуре A-B-C без отмены; одно событие на структуру. Пункты 1–9 запоминаются
  на этом баре (эталон `reference/map.py`, тот же автомат, что в Pine).
- **Сделка** нужна только для оценки признаков: вход — open следующего бара (без заглядывания
  вперёд), стоп и цель — см. выше. Если стоп и цель попали в один бар, считается стоп.
  Если вход уже за стопом или за целью, сделки нет.
- **Метрики:** число сделок, доля целей, средний R после комиссии, PF, максимальная просадка в R.
- **Вклад пункта** — сравнение событий, где пункт ✓, с событиями, где он ✗, отдельно по двум
  периодам. «—» (нет данных) не входит ни в одну группу.
- **Пометки:** «⚠ <30» — выборка меньше 30; «периоды противоречат» — у среднего R разный знак;
  «вклад меняет знак» — разница «с признаком − без» в двух периодах разного знака.

## Ограничения

- Пункты не независимы: например, 6, 7 и 8 почти всегда выполняются вместе в момент слома
  структуры, поэтому группы «без признака» для них маленькие.
- События пересекаются во времени между соседними структурами, сделки не независимы.
- Модель исполнения упрощённая: нет проскальзывания и частичных исполнений, стоп исполняется
  точно по уровню.
